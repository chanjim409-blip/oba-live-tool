# 旧宿主停刷快照迁移工具（仅准备）

- 新增两阶段工具：`capture` 只读取本机旧宿主已缓存的 preflight（不刷新平台），将 `manual/blocked + restricted=true`、两个时间、固定端口写为系统私有的 HMAC 完整性快照，剔除账号、房间、弹幕和凭据。旧时间只代表“待人工复核”，不是平台当前限制的证明。
- `migrate` 需要旧端口不再监听，并在迁移全程独占该端口；核对 Windows 所有同端口监听者和已知宿主/Electron 进程。先建立新宿主识别的故障锁，再校验快照、用 SQLite 独占写事务持久化旧停刷、复读确认；成功后只删除自身创建的标记并释放端口。缺证据、文件异常、活跃进程或数据库并发时不清锁、不覆盖旧数据，失败后保留标记待人工排查。
- 已存的其他合法停刷原因不覆盖；重复迁移幂等；快照仅新增不覆盖。工具不结束进程、不调用平台、不启动浏览器或服务、不删除原有停刷，也不修改用户登录资料。
- 对照合成测试覆盖签名篡改、旧端口占用、主机进程检查失败、写入期间进程变化、已有标记、数据库并发和重复迁移。任何本机管理员进程若不遵守宿主和 SQLite 约定，仍可在检查后主动破坏数据；系统外故障无法被软件保证避免。
- 读取快照响应限 16 KiB，Windows 路径越界使用 `path.sep` 校验。迁移前对数据库/WAL/SHM 同时检查 Windows 独占句柄，之后仍取得 SQLite 独占事务；合成测试验证已有连接拒绝。
- 宿主全量离线回归 65/65、类型检查及两端协议 4/4 通过。不提供强制终止入口；旧宿主无正常退出接口时，迁移检查将拒绝，不诱导强停。
- **未真实运行 capture 或 migrate。** 真正迁移仅在旧宿主正常结束、用户知情的安排下进行；保存停刷不等于用户已检查或可开启发送。
