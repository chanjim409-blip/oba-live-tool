# 停刷期间人工查看入口（离线开发）

- 增加仅供用户明确请求的人工查看窗口：要求宿主存在已持久化的停止原因、所有发送开关关闭、原回复浏览器未运行，走现有本机鉴权与来源检查；不更改/清除停刷，不自动完成验证或发送。
- 复用已配置的自有账号 profile，不读取或打印账号身份、凭据；启动前在 Windows 按进程命令行核对 profile 未被 Chrome/Edge 持有，核对失败拒绝；新会话创建自有独占租约并再次核对。不能识别占用、残留租约或 profile 别名时停止，不删除其他 Chrome 的文件。
- 用户确认后仅打开官方个人页面供手动检查；不自动访问直播间、监听评论、填写验证码或刷新。窗口关闭也不清除持久停刷；不能因查看成功推定身份或权限。
- 用户需要在打开的窗口中自行进入目标直播间并检查原先的验证提示；个人页面正常、开窗成功或窗口关闭都不能证明直播间限制已解除。手动关闭窗口后租约保留至宿主有序关闭；异常中断的残留租约不能自动删除或自动重开。
- 请求和成功事件加入既有无敏感字段的停刷审计，期间停止状态变化、存储错误、客户端断开都关闭自有窗口并拒绝。
- 该入口仅在新代码被安全加载后才存在；现运行旧宿主不能热更新。旧宿主的限制缓存必须在人工确认、旧 profile 安全释放及停刷迁移后仍被保留，不能调用旧 complete 或绕过已拒绝的强制终止。
- 合成测试检查 profile 占用与并发、认证和来源、严格输入、存储失效、发送开关、停刷与重启；不调用真实平台。无真实打开、发送或部署。
